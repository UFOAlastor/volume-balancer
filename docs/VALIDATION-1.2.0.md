# 1.2.0 验证记录与边界

本记录说明自动网页音频处理、高音量增强及恢复机制的数字验收范围。数字输出验证不能代替人工试听或所有网站的兼容性保证。

## 已验证

- Microsoft Edge 156.0.4314.58，独立临时配置，正常自动播放策略，初次处理前不打开扩展或授予整页捕获权限。
- 167 项 Node 测试、版本/资源检查、7 项真实界面检查通过。
- Bilibili、YouTube 的公开 MSE 视频及 W3Schools 公开 MP4，在网页正常播放后获得非零的处理输出。另测本地原生 audio/video、跨域受限时回原声。
- Bilibili 与 YouTube 实际拖动音量、用户静音、关闭自动处理、卸载和刷新后，分别保留约 43% 与 40% 的网站音量。两站均有启用扩展时切换到另一视频并处理成功的记录。
- 最终观察器及可信输入工具下，两站各三轮完整流程通过，共六个独立临时配置；故障注入 12 组、原生媒体生命周期 15 场景通过。此前的失败和诊断记录保留，未计作合格轮次。
- 原生媒体夹具覆盖暂停/恢复、用户零音量、原生键盘调到零、停止、处理器停止上报、上下文暂停、重载、同 ID 更新、禁用、卸载、渲染进程崩溃后刷新及替换音源。
- 安静夹具的最终输出幅度：200% 为 100% 的 2 倍，500% 约为 7.06 倍。0–200% 的对照 PCM 保持旧处理结果；500% 对合成瞬态素材的 RMS 比旧 500% 增加约 6.25 dB。这些是数字测量，不能代替真实素材听感。

## B站旧零输出判定的根因

旧验证器等到视频已可播放后才安装 connect 探针，漏掉此前已经建立的输出图。同型报错的连续记录显示：所选视频持续输出并播完约 11.3 秒，之后自动切换下一条；12 秒超时只看到了下一条开头，单次时间快照不能证明播放时钟卡住。独立前置分析器在报错时测得非零的最终输出。确定性本地对照也证明：已有输出图正常工作时，迟装探针仍会记录不到连接。

因此修正的是观测顺序与失败推断，没有给播放器加入时钟或振荡器 workaround。原始旧记录没有底层音量，不能事后补造；恢复能力由本轮独立底层读取、真实生命周期及故障注入分别验收，不能用网站可见的音量替代。

可复现脚本位于 [verification](../verification/INSTRUCTIONS.md)。真实站点使用独立仪器化副本，观察脚本在 document_start 前置；原 29 个程序/资源文件逐字节一致，测试 manifest 只增加观察脚本，版本、权限及其他字段不变。正式 ZIP 不含测试观察器，另做原包基础回归。真实站点验证不使用 Debugger；只有自有夹具的冻结边界实验使用调试暂停。

## 客观限制

- 全部声音验证使用独立浏览器的无声硬件输出端；记录处理器及最终门控后的 PCM 和浏览器播放状态。没有人工试听或物理音频回录。
- 暂停测试页全部 JavaScript 1700 ms 时，租约虽过期，底层音量仍为 0；恢复页面执行后才恢复到 0.37。这直接说明恢复代码不能执行时的客观边界，并不是操作系统强制杀死所有进程的实测。
- 禁用/卸载后的恢复依赖仍能执行的页面守卫；如果页面、守卫和恢复代码一起被强制终止或冻结，扩展不能保证立即恢复。没有对操作系统强制终止所有相关代码作无条件保证。
- DRM、不可读跨域媒体、纯 Web Audio 合成、浏览器内部页、站点访问被限制、播放器重写接口等不属于已验证的全面自动处理范围。整页捕获仍需要浏览器授权。
- 测试为 macOS 上的解压扩展；不等同于 Edge 商店签名更新、Windows、所有编解码器、长期运行或所有进程崩溃类型的验收。
